## 2. 需求确认（关键决策记录 ADR）

### ADR-01 预测目标范围
**决策**：覆盖 `targets.yaml` 全部 5 个软测量目标，指标字典驱动，每指标独立建模。
**理由**：目标指标清单尚未最终完善，统一框架保证"新增指标只改 yaml、不动代码"。

### ADR-02 任务定位
**决策**：纯软测量（推断当前真实值），不做前瞻预测。
**理由**：与 TCN 职责边界清晰，避免第一步范围膨胀。

### ADR-03 数据 schema 归属
**决策**：由我方设计统一 schema：高频实时表 + 低频化验表 + 指标字典映射，先落 SQLite。
**理由**：现场表/PLC 协议未定，先用可演进的宽表 + 元数据字典承接。

### ADR-04 评估切分
**决策**：按时间切分（train_ratio=0.8）+ walk-forward 滚动验证，**禁止随机切分**。
**理由**：时序数据随机切分会数据泄漏；后续真实数据上线以 walk-forward 为验收口径。

### ADR-05 演示数据
**决策**：生成合成 demo 数据（按指标字典特征范围 + 工艺关系 + 噪声）跑通全管线。
**理由**：真实表就绪前验证框架正确性，真实表就绪后同结构替换。

### ADR-06 交付形态
**决策**：训练/评估/预测 CLI + 可 import 的预测库（`SoftSensorPredictor`），暂不做常驻服务。
**理由**：后续接大模型/控制模型时再上 FastAPI，避免第一步过度设计。

### ADR-07 占位值（真实表就绪后仅改配置）
采样周期 300s、化验周期 2h、特征窗口 60min、液位滞后补偿 -90s、集成方式 weighted。

## 3. 架构设计

### 3.1 目录结构
```
├── config/          settings.yaml（数据/切分/超参）+ targets.yaml（指标字典）
├── src/dmdcs/
│   ├── config.py            配置加载
│   ├── data/                demo生成 / 加载(CSV+SQLite) / 窗口特征 / 化验对齐
│   ├── models/              base / xgb / lgbm / ensemble（统一接口，TCN 可插）
│   ├── training/            指标计算 / 时序切分 / 训练管线 / 评估
│   ├── serving/             SoftSensorPredictor（单条/批量）
│   └── utils/               模型持久化 / JSON / 日志
├── scripts/         gen_demo / init_db / inspect_db / train / evaluate / predict
├── db/schema.sql    真实数据 5 张表 DDL
├── data/            raw（实时/化验 CSV）+ templates（填数模板）+ processed（对齐宽表）
├── artifacts/       模型产物 + meta.json + report.json + summary.json
└── docs/            数据表设计 / 问题清单 / 本纪要
```

### 3.2 数据流
```
PLC/仪表/在线仪表 ──> realtime_signals（高频，宽表）──┐
                                                    ├─> 对齐（化验时刻前向窗口聚合
化验室/LIMS ──────> lab_assays（低频化验真值）───────┘    last/mean/slope）──> 训练
指标字典 indicator_dict：定义每列 来源/周期/范围/滞后 ──> 训练自动检测数据库或 CSV
```

### 3.3 模型接口（BasePredictor）
`fit / predict / feature_importance` 统一接口；XGB、LGBM 已实现，TCN 后续按同接口接入，
`EnsemblePredictor` 通过 `add_member` 支持任意数量成员。

## 5. 遇到的问题与解决

| 问题 | 根因 | 解决 |
|---|---|---|
| pip 安装 20 分钟无进展 | 沙箱环境无外网（0 TCP 连接、缓存不增长） | 改用清华镜像由用户手动安装 |

## 6. 验证结果（demo 数据，测试集按时间切分）

| 目标指标 | 最佳模型 | R² | RMSE |
|---|---|---|---|
| 精煤真实灰分 clean_ash | lightgbm | 0.723 | 0.329 |
| 介质粘度 medium_viscosity | ensemble | 0.809 | 0.250 |
| 精煤水分 clean_moisture | lightgbm | 0.856 | 0.226 |
| 悬液密度 suspension_density | xgboost | 0.586 | 0.0034 |
| 回收率/产率 recovery | xgboost | 0.381 | 1.361 |

**重要观察**：
1. 加权集成被 XGB 拖累（clean_ash：LGBM 0.329 vs 集成 0.404）→ 真实数据下评估
   `ensemble.method: best` 或 stacking（见 issue-checklist P1）
2. recovery 最难预测（R²≈0.38，LGBM 为负）→ 需补特征（密度/灰分仪读数/可选性）
3. demo 数据关系相对简单，真实数据 R² 可能更低，属正常

# 粗精煤泥灰分模型优化与验证

已保留“每次采样一条预测”和“按日”两种口径，页面原来的“按班次”更名为“按采样”。优化降低了本次后期检验误差，但尚不能证明模型已达到稳定生产预测水平。专家提出的原煤灰分、脱粉系统是候选建模依据，不被直接写成固定影响权重。

## 数据审计

页面现提供 **DS / GPT** 切换：DS 是原版，GPT 是本说明中的优化版。按采样和按日视图一起切换，两套模型独立保存；按钮选中状态与当前实际模型一致，已有 GPT 存档不会被标成 DS。新安装默认 DS，已有存档保留当前版本。第一次切到尚未训练的版本时，使用当前范围训练；以后可直接复用，重训只更新选中的版本。

切换会同步更新粗灰预测取值链（包括其他页面引用的采样模型预测），实际化验值保持原数据。新增数据后，比较两版前应分别重训。DS 保留留一验证 Q²、原版采样模型时间选型、日开关多数状态；GPT 保留按日分组时间调参与嵌套时间验证。二者 Q² 定义不同，页面分别注明。两版按日训练都遵守范围选择，修复旧日模型忽略范围的问题；缺失因子按训练均值填补。

该切换功能用于保留原版并继续验证优化版，不代表 GPT 已被证明优于 DS。通常每天一次化验时，应按独立日期/化验批次评价；同日多条记录不能等同于多次独立反馈。

只读使用用户提供的“新”目录中的两份粗精煤泥影响因素工作簿，未修改原文件，也未替换现场数据库或当前保存的生产模型。

## 模型改动

1. **按完整日期向前验证。** 同一天的采样全部位于同一侧。内层只用过去数据选择参数和算法；外层评估整个选择流程，避免选模型时看到外层检验标签。填补均值、标准化、常量列识别均在各自训练折内完成。
2. **增加稳定性约束。** MLR使用标准化岭回归，正则化候选为样本数乘以 `0.001 / 0.01 / 0.1 / 1 / 10`。PLS候选为1–4个成分，专家三因子版本最多3个。
3. **检验专家假设。** 比较十因素、仅原煤灰分与473/474脱粉三因素，以及对其他因素施加4倍正则化惩罚的候选。4倍惩罚不等于原煤/脱粉占4倍物理影响，不强制系数正负或排名。
4. **修正按日聚合。** 连续因素取有效采样均值；开关保留采样点开启比例。例如一半采样时开启记为0.5，旧版多数表决会记为0。它不是设备全天运行时长占比，也不是煤量加权日灰分。
5. **统一页面口径。** 按日模型遵守所选训练范围；数据、范围或容差变化会使缓存失效。卡片、趋势、表格和因子图使用所选算法。数据不足时清空旧模型展示。
6. **区分拟合与验证。** 页面展示历史对照及嵌套时间验证，并给出历史均值基线。“影响权重”改为“模型关联强度”，标准化系数不能解释为因果贡献。
7. **修复重训同步。** HTTP模式先同步数据，再带版本号训练；后端返回新版本，前端只保存已落库结果。同步冲突或训练失败会明确提示，不再静默切换为另一份本地模型。

十列系数的结构保持兼容，既有模型可继续读取。采样模型至少需要12条有效记录、8个日期；日级模型至少需要12个有效日期。旧模型不会自动覆盖，重新训练后才应用v2。

## 固定后期检验

先固定6–7月作为开发集，在其中按完整日期向前调参，再对8–9月检验。后期数据不参与这个检验模型的参数选择。旧采样模型按旧流程重训；旧日级模型按旧多数表决聚合与留一验证选型重训。所有方案使用同一批可用源数据。

MAE、RMSE单位均为**灰分百分点**，合格率指绝对误差不超过0.8个百分点。

| 口径 | 模型 | MAE | RMSE | R² | ±0.8合格率 |
|---|---|---:|---:|---:|---:|
| 按采样，39条 | 旧流程 | 2.331 | 3.144 | -0.229 | 30.77% |
| 按采样，39条 | 优化流程 | **1.996** | **2.854** | -0.013 | **38.46%** |
| 按采样，39条 | 开发集历史均值 | 2.199 | 2.946 | -0.080 | 23.08% |
| 按日，11天 | 旧流程 | 1.856 | 2.011 | -1.050 | 9.09% |
| 按日，11天 | 优化流程 | **1.431** | **1.716** | -0.493 | **36.36%** |
| 按日，11天 | 开发集历史均值 | 1.377 | 1.600 | -0.298 | 36.36% |

采样MAE降低约14.4%，按日MAE降低约22.9%。但两种模型的后期R²仍为负，按日模型还没有超过历史均值基线。不能把这次改善表述为“高精度预测”或直接作为自动调控依据。

专家假设的开发集消融结果：仅三因素时，采样时间验证RMSE为3.750，保留其他因素后为3.252；按日分别为1.748与1.694。本批数据支持保留原煤、脱粉作为重点候选，同时保留液位、带煤量、系统组合等信息。不能据此认定液位是主要物理原因，也不能认定专家判断错误。

## 全量训练与后期检验的区别

导出的JSON另含使用全部152条/37天训练的模型参数，供复核。它们不是上表使用的检验模型，不能在同一批8–9月数据上再次宣称独立验证。

全量数据的嵌套向前验证中，采样预测MAE为2.133、RMSE为2.870（41条外层验证记录）；按日MAE为1.053、RMSE为1.302（12个外层验证日期）。第二个外层窗口允许使用已经过去的8月记录重训，体现滚动学习的效果，因此与“仅6–7月训练”的固定后期检验结果不同。

即使按日误差较小，也不能等同于采样预测已经达到这个精度。按日目标是采样平均灰分；当日全部工况平均值只有采样完成后才完整，不应提前用于班初预测。

## 使用与复现

- 若源数据已导入，在粗精煤泥页面选择训练范围并点击“重新训练”。选择“全部数据”可使用现有8–9月记录；“仅6–7月”保留历史开发口径。
- 页面显示“旧版模型，建议重新训练”时，说明当前保存的模型还没有应用v2。重训完成后检查嵌套时间验证，不能只看历史对照R²。
- 若部署的后端仍是旧进程，需要更新并重启后端，确保前后端运行同一版本。
- 原始工作簿的哈希、排除单元格、评估数值和全量模型参数保存在 `docs/coarse-model-evaluation.json`。

```powershell
python backend/scripts/evaluate_coarse_models.py --source-dir "C:\Users\25925\Desktop\web(2)导入数据\新"
node backend/scripts/refresh_algorithm_goldens.js
node backend/scripts/verify_coarse_models.js
cd backend
python -m pytest -q
```

评估脚本只读取Excel、输出JSON，不访问数据库。需要项目依赖中的openpyxl。v1夹具 `train_js.json` 保留为历史求解器基线，v2夹具为 `coarse_v2_js.json`。

## 下一步优先事项

1. 核对上述三处315灰分错误，补齐原煤化验批次、采样时间、结果获得时间和有效区间，确认夜班日期口径。这比继续堆模型复杂度更优先。
2. 脱粉除开/停外，补采两路运行时长、实际处理量、分流比例，以及启停时间。先核实现场实际可提供的测量点，避免把缺失值当“停”。
3. 保存工作面组合和混配比例，配合采样批次核对。当前只有工作面名称，无法可靠区分原煤性质变化与系统切换的共同影响。
4. 锁定下一批新日期作前瞻检验，保留每次预测时使用的特征、模型版本和生成时间。对比历史均值、现有v2及后续候选；按脱粉状态分别查看误差及样本数。
5. 有了明确的工艺滞后和足够启停样本后，再评估“原煤灰分×脱粉状态”等交互项和滞后特征。优先要求跨日期稳定优于基线，再讨论用于前馈控制。

# GPT 独立优化与预测检验（第二轮）

本轮只优化粗精煤泥 GPT。DS 的算法、参数、日级聚合、保存模型与原版对拍基线保持不变。DS 仅参加只读效果比较，没有将其流程复制成 GPT。改动未写入现场数据库，未提交或合并 main。

## 数据与独立判断

使用当前数据库152条有效采样、37个日期，覆盖2026-06-16至2026-09-03；输入哈希与第一轮完全一致。7月14日至8月23日相隔40天，后期474脱粉在记录中持续关闭。模型对训练中覆盖不足的状态继续线性外推，是本轮发现的一个具体误差来源。

这批数据只有37个有效日期，原煤灰分与日均粗灰的整体相关性约0.087。专家判断用于提出“原煤与脱粉联合作用”的假设，不能直接据此强行规定系数或权重排名。

开发期比较了工况交互、稳健拟合、近期化验校正、相似工况估计与候选集成。复杂交互和额外近期化验输入没有表现出稳定改善，未接入正式预测。保留的是有明确作用范围且两种口径的既定历史检验均未退步的改动。由于这些数据已参与多次方案探索，结果属于开发期复核，不能视作新的独立验收。

## 最终实现

### 工况覆盖约束

GPT 的每次训练只用该训练窗口计算各因素的最小值与最大值。预测遇到超范围因素时，使用最近的训练边界值作保守估计，停止沿未验证的斜率继续外推；原始输入保持原值。例如训练中的474日采样开启比例最低是0.5，而新日期为0，则模型暂按0.5边界估计，不能声称已经学会“全天关闭”的影响。

模型新增 `inputPolicy=clip-training-range` 和 `inputBounds`。边界参与内层验证、外层验证、前后端预测、日级图表和服务端保存后重载，避免评测使用一种公式、上线使用另一种。页面只在GPT中显示超出训练范围的条数/天数，以及保守估计说明。

该策略仅检查单个因素的范围，不检测未见过的因素组合。范围内也不代表预测一定可靠；范围外应补充对应工况数据，而不是长期把边界估计当作已验证规律。

### 日级稳健拟合与MAE选参

日级MLR比较普通岭回归与Huber稳健岭回归，正则强度为0.03/0.1/0.3/1。Huber使用固定1.5灰分百分点拐点、8次迭代加权求解，降低极端残差对系数的牵引，不删除记录，不随页面合格容差变化。

日级参数依据向前时间验证MAE与留整日验证MAE的等权平均选择，MLR/PLS之间再比较向前时间MAE。采样模型保留原候选及RMSE选参，本轮只增加覆盖约束；它的噪声结构与日均数据不同，直接套用日级改法在开发试验中并不稳定。

保留十个输入因素和原来的日均聚合，未把采样点开启比例解释成全天运行时长。最终全量日模型选择稳健MLR、alpha=0.3；全量采样模型仍为原配置。新增版本标识 `gpt-coverage-robust-20260922`，兼容格式仍为version=2。

### 近期化验校正的处理

用户确认化验当天出结果，但记录没有具体出报告时间。试验保守地仅使用前一天及更早、最多3天内的化验，按每日残差均值进行时间加权，再比较0/0.25/0.5校正强度。它可以使用较早测试日期已获得的化验，信息条件不同，因此单独列为额外输入试验。

校正强度0.25时，采样向前MAE从2.127变成2.138，日级从0.813变成0.808；强度0.5时两者都退步。日级约0.005的开发期变化不足以支持部署，正式模型未启用该校正。结果与算法可通过本轮评估脚本复核。

## 使用、验证与下一步

- 当前仍建议“全部数据”。近30天仅11个有效日期，不适合单独训练十因素日模型。
- 更新代码并重启后端后，在GPT中选择全部数据重新训练采样模型；日模型随页面数据重算。现有模型不会因这次文件编辑自动改写。
- 本地165项pytest通过，实际152条数据的采样/日级JS-Python模型逐值对拍误差小于1e-6；DS原版对拍、存档隔离、DS→GPT→DS页面回归通过。测试使用临时库或浏览器内存。
- 回测默认每条/每日输入工况在预测时可用。原始记录没有完整的输入到达时间，日均输入也需当日采样完成；不能据此宣称提前一天预测已有相同精度。
- 下一阶段锁定新日期，保存预测时间、当时可用的输入、模型版本和预测结果，化验出来后再核验MAE、容差合格率及大误差。优先补充474关闭、工况切换和极端灰分日期，停止在同一批历史数据上反复追求更漂亮的成绩。

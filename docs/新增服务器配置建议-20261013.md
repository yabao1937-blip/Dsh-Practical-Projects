# 重介密控系统新增服务器配置建议

供厂内信息部门申请虚拟机或采购实体服务器使用。新增服务器运行重介密控系统的 Web、只读 OPC UA 采集、SQLite、小时简报及决策归档，原 10.255.1.21 服务器继续运行 KEPServer。建议优先申请厂内现有虚拟化平台上的独立虚拟机；平台容量、系统兼容及授权由信息部门核定。

配置核查日期为 2026 年 10 月 13 日。当前点表为 30 个点位，轮询与历史保存间隔均为 5 秒；此前现场点表曾为 50 个点。以下按当前规模并预留点位、历史和独立调试环境的余量规划，属于工程配置建议，尚未经新服务器压力测试。

## 推荐虚拟机配置

| 项目 | 申请配置 |
|---|---|
| CPU | 4 vCPU，支持 x64；预留扩至 8 vCPU 的能力 |
| 内存 | 16 GB，预留扩至 32 GB 的能力 |
| 系统盘 | 100 GB，SSD 支撑的数据存储 |
| 数据盘 | 400 GB，SSD 支撑、低延迟、支持在线扩容的数据存储 |
| 网络 | 1 个虚拟网卡，接入厂内业务网络；宿主机使用千兆或更快网络 |
| 操作系统 | Windows Server 2022 Standard x64，带桌面体验，使用有效授权 |
| 备选系统 | 厂内平台已验证兼容时可选 Windows Server 2025 Standard x64，带桌面体验 |
| IP | 独立固定厂内 IP，由信息部门分配，不复用 10.255.1.21 |
| 备份 | 独立备份存储，初始至少 1 TB 可用容量，支持扩容 |
| 运维 | 远程桌面、独立运维账号、开机启动、故障重启、日志轮转和磁盘余量监控 |
| 运行方式 | 7×24 小时；宿主机应具备电源保障，确认实际可用资源后分配 |

500 GB 为虚拟磁盘标称容量，文件系统格式化后的实际可用空间略小。系统盘与数据盘逻辑分开便于运维，但两者若落在同一存储设备，并不形成故障隔离；备份应位于另一套独立存储，并保留异机副本。SQLite 文件应保存在虚拟机内部的磁盘文件系统，不直接放 SMB 共享文件夹。

Windows Server 2022 的扩展支持期至 2031 年，2025 至 2034 年。选型优先考虑厂内虚拟化平台、运维工具和授权已支持的版本。[Windows Server 2022 生命周期](https://learn.microsoft.com/en-us/lifecycle/products/windows-server-2022)、[Windows Server 2025 生命周期](https://learn.microsoft.com/en-us/lifecycle/products/windows-server-2025)

## 采购实体服务器时的配置

| 项目 | 采购规格 |
|---|---|
| 机型 | 适合现有机房的塔式或机架式服务器，支持长期连续运行 |
| CPU | 至少 8 核的 x64 服务器处理器，供应商确认兼容所选 Windows Server |
| 内存 | 32 GB ECC，支持扩至至少 64 GB |
| 存储 | 2 块至少 960 GB 的企业级 SSD，支持断电数据保护，组成 RAID1 |
| 可用容量 | 2×960 GB 镜像后标称可用约 960 GB，实际格式化空间略小 |
| 网络 | 至少千兆以太网；双网口便于后续冗余或运维分离 |
| 电源 | 机房提供 UPS 或配套 UPS，按整机实际功率选型，支持断电安全关机 |
| 远程管理 | 配备带外管理能力，便于远程查看硬件状态和处理故障 |
| 操作系统 | 与虚拟机方案相同，供应商提供相应驱动及有效系统授权 |
| 备份 | 另配至少 1 TB 初始可用独立备份空间，支持扩容和异机副本 |
| 服务 | 至少 3 年保修，明确故障响应和硬盘更换服务 |

RAID1 用于容忍单盘故障，不能代替数据库备份。采购报价应包含磁盘、RAID 实现、系统授权、保修及必要的电源配套，不仅报价主机裸机。

当前项目使用 CPU 运行统计模型，无需独立计算 GPU。4 vCPU/16 GB 的虚拟机适合本次起步；实体服务器配置更多考虑可靠性、维修和扩展余量。若将来在本机增加大型语言模型推理，应另行评估，不能沿用本次容量假设。

ECC 和千兆网络也符合微软公布的物理服务器硬件要求；应用资源规格仍应通过实际负载验收确定。[Windows Server 硬件要求](https://learn.microsoft.com/en-us/windows-server/get-started/hardware-requirements)

## 网络和部署位置

业务链路为：

~~~text
厂内用户浏览器
       │ HTTP，初期使用 8000 端口
       ▼
新增应用服务器
Web + collector + 本机 SQLite
       │ OPC UA，TCP 49320
       ▼
原服务器 10.255.1.21
KEPServer
~~~

信息部门需提供或确认：

- 新服务器能够连接 10.255.1.21 的 TCP 49320，并完成真实 OPC UA 会话和点位读取验证。
- 原 KEPServer 所在服务器允许新增应用服务器接入；只对规定厂内来源放行。
- 厂内授权用户能够访问新服务器的 TCP 8000。后续如使用 HTTPS，可由厂内网关统一提供 443。
- 运维远程桌面仅向授权管理终端开放。
- 配置正确的网络掩码、必要路由、网关、DNS 和统一时间源；时间显示按北京时间。
- 新服务器不能与旧服务器使用相同 IP。10.255.1.21 是原 KEPServer 地址，不是待分配的新应用服务器地址。

Web 与 collector 均部署在新服务器，共用该机本地 SQLite。正式 Web 采用 1 个 Uvicorn worker，采集使用独立进程。Nginx 不作为本次采购和部署必备项；后续需要 HTTPS 或统一访问入口时再评估反向代理。

保留 Python/JS 源码、接口文档和服务日志供调试。代码与数据库副本可用于独立调试实例，按需运行在 127.0.0.1:8001，避免与正式库混用。调试副本默认关闭真实采集。

## 存储和备份容量依据

30 个点位每 5 秒全部保存一次，理论约 518400 条点位历史记录每天；扩至 50 点约 864000 条，扩至 100 点约 1728000 条。它们是采样量估算，不是实际每日磁盘增长量，不能直接推算可保存年数。

文档初次检查时主库约 700 MiB，并持续写入。2026-10-14 起原始采集历史、决策档案和小时汇总永久保留；旧 7 天自动清理已经取消，逐次决策只做无损压缩归档。因此建议初始分配 400 GB 数据盘并允许扩容，监测上线后至少一周的实际日增量与峰值 I/O。

每日创建 SQLite 一致快照并独立保存；按永久存储要求，不设置自动删除旧备份的天数或份数限制。已有强制覆盖前自动备份也会额外占用空间，需纳入总容量。1 TB 是初始备份容量建议，不是长期容量保证。库达到几十 GB 后，完整多版本备份的总量应重新计算并扩容。

磁盘剩余空间低于 20% 时发出容量告警并安排扩容，或将完整历史无损迁移到更大存储后验证恢复与查询。不能通过删除原始数据或旧备份满足容量要求。

## 交付验收

1. CPU、内存、实际可用磁盘、操作系统及固定 IP 符合申请配置，虚拟化宿主机有实际余量。
2. 新服务器能访问 KEPServer，采集质量正常、时间戳持续更新。
3. 完整数据库一致快照迁移后，原 DS/GPT 模型、来源选择、补录、反馈和历史均保留。
4. Windows 的 Web 和 collector 两个服务可自动启动、失败恢复，日志正常轮转。
5. 关闭网页和断开远程桌面后，采集、决策归档及小时简报继续运行。
6. 通过新环境的隔离回归及 DS 原版对拍，不修改或重新生成 DS 基线。
7. 新服务器维护重启后服务自动恢复；完成一次异机备份恢复演练。

Python 依赖按项目锁文件安装，使用新的虚拟环境。旧服务器为 Windows Server 2008 R2，无法直接使用本项目 Python 3.11 环境；新设备的操作系统和运行时需满足官方支持及项目依赖要求。[Python Windows 支持说明](https://docs.python.org/3.11/using/windows.html)

## 可直接提交的信息部门申请文本

申请新增一台厂内重介密控系统应用服务器，优先使用独立虚拟机，配置为 4 vCPU、16 GB 内存、100 GB SSD 系统盘和 400 GB 可扩容 SSD 数据盘，安装有效授权的 Windows Server 2022 Standard 64 位桌面体验版，分配独立固定厂内 IP，配置至少 1 TB 初始可用独立备份空间。该服务器需能访问 10.255.1.21:49320 的 KEPServer，为授权厂内用户提供 8000 端口访问，并提供远程运维、7×24 小时运行、开机服务启动、日志轮转和备份恢复能力。厂内已验证支持 Windows Server 2025 时可选用该版本。若采购实体服务器，则按 8 核、32 GB ECC、2×960 GB 企业级 SSD RAID1、千兆网络、UPS/机房电源保障和至少 3 年保修配置。

# 决策总览实时链路

适用页面：决策总览 → GPT 链路。用户确认当前密度采用 A304，目标总灰分为 8.5–9.0%；范围内保持，范围外向最近边界调整。

## 数据与计算

每轮采集刷新、补录刷新或卡片选点变化，页面将同一份采用值、单位、来源、时间和状态提交到 `POST /api/v1/decision/snapshots`。接口从 SQLite 一致读事务加载保存模型和动作保护状态，依次计算：

1. 调用已有 GPT 保存模型预测粗精煤泥灰分。10 个因素均须有效；当前生产模型为 GPT 时采用当前模型，否则读取独立 `coarseModelVariants.gpt`。不回退 DS，不自动训练，不用均值填造缺失输入。保存模型标记了训练范围限幅时才执行该限幅，详情显示原值与模型采用值。
2. 重介精煤量 = `501/COAL_CAP + 502/COAL_CAP − 浮精量 − 粗精煤泥量`。501、502 须同源、同接收时刻、批次一致；单位均为 t/h，计算前不四舍五入。负平衡或零总量不给总灰分。
3. 总灰分 = `(重介灰分×重介量 + 浮精灰分×浮精量 + GPT粗精灰分×粗精量) / 三组分总量`。
4. 以 `TIA_4_1.TIA_4_1.A304/MD` 为当前密度，目标在范围内取本次总灰分（保持），低于范围取 8.5，高于范围取 9.0。沿用原专家调整律、0.05 个百分点死区、默认每步 0.02 g/cm³ 限制及动作闩锁/驻留保护；不重新添加原理论密度范围的硬截断。范围外偏差未超过死区时仍保持，并说明原因。

默认模型点位：原煤灰分 `202/ASH_R_INS`、入洗量 `301/COAL_CAP`（t/h）、精磁尾液位 `JMCWC/LEVEL_B`、四系统运行组合、473/474 脱粉组合。只在未保存过来源选择时自动绑定唯一对应点位，尊重已选来源和明确清空。重介灰分继续优先自动绑定已有 SQLite 手工补录；浮精灰分及两种煤量按各自卡片当前来源采用，详情保留人工/历史/默认来源标记。

A304 固定作为当前密度，不提供选点切换。为 1 或缺失时只沿用本路最近有效非 1 数据。停机因素依据当前入洗原煤原始读数是否 ≤10 t/h，不能用停机回退的历史非零值判断运行。

## 缺失与刷新

- KEP `good` 输入在后台再次核对接收时间：超过 30 秒或未来超过 5 秒则不可用；避免页面从后台恢复时旧缓存被重新当作当前数据。手工、历史、默认来源按既有采用规则处理，不冒充实时测量。
- 原煤灰分/原煤量为零按原规则沿用并标设备停机；模型及总灰分可显示带“沿用输入”标记的观察结果。任一必要输入沿用、停机、断线、质量异常、单位不符或缺失，暂停新的调密建议并显示原因。
- 旧请求晚返回不会覆盖新输入；计算接口失败时清掉旧建议。采集恢复后自动重算。正常刷新约每 5 秒，计算只在页面可见时进行；KEP 后台采集继续独立运行。
- 闩锁驱动时间来自灰分及煤量输入，单独刷新密度不视为新灰分；未被本次采用的旧人工数据不释放驻留保护。

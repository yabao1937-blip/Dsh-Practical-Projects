# 业务指标手工补录

入口：数据采集与补录 → 业务指标补录。

| 补录信息名 | 单位 | 数值范围 |
|---|---|---|
| 重介精煤灰分 | % | 0–100 |
| 原煤煤泥含量 | % | 0–100 |
| 粗精煤泥量 | t/h | 非负有限数值 |

填写时间、信息名和值后点击“保存补录”。时间留空时，使用提交时的服务器当前时间；填写的时间按北京时间解释。保存确认来自数据库提交结果，网络失败时保留输入，可核对记录后重试。

记录写入 `backend/data/dense_medium.db` 的 `manual_measurements` 表。`observed_at` 是测量时间，`created_at` 是入库时间，两者保存为 UTC ISO 时间，页面统一显示北京时间。信息名和值分别在 `name`、`value` 列，单位在 `unit` 列。

下方记录从数据库读取，支持按信息名筛选和分页，按录入顺序显示。其他电脑或浏览器打开同一服务器页面后也能查询；点击“刷新补录记录”可读取最新记录。

三类补录通过独立接口保存，不加入旧整库浏览器镜像。当前功能负责保存和展示测量记录；不会自行把它们写入模型训练数据、改变模型输入或启动粗精煤泥灰分预测。

接口：

- `GET /api/v1/manual-measurements/metrics`：可补录信息名和单位。
- `GET /api/v1/manual-measurements?metric=...&limit=20&offset=0`：记录查询。
- `POST /api/v1/manual-measurements`：新增补录，沿用项目写接口权限。

提交字段为 `metric`、`value`、可选的 `observed_at` 和 `client_id`。`client_id` 用于处理“服务器已保存但浏览器未收到响应”的重试；同一标识和内容重复提交会返回原记录，改用不同内容会返回冲突。

三项内部标识分别为 `heavy_clean_coal_ash`、`raw_coal_slime_content`、`coarse_slime_amount`。已有“仪表与采样补录”继续保留原有用途。

## 决策总览中的手工补录点位（2026-10-08）

流程：前端提交 → SQLite `manual_measurements` 提交成功 → `GET /api/v1/manual-measurements/latest` 从数据库查询 → 决策总览点位和卡片显示。

新接口为上述三个指标各提供一个稳定的“手工补录”点位。最新值按测量时间 `observed_at` 降序选择；同一测量时间取最后录入的 ID。补录较早测量时间不会顶替较新读数，未来测量时间到时后才采用。审计列表仍按录入顺序排列，显示所有记录。

重介精煤灰分没有明确选择来源时，自动选用已有的最新手工补录；已经选择的其他点位继续保留。也可以在卡片详情的“选择卡片显示点位”中选择“手工补录 · 重介精煤灰分”。明确清空选择后，刷新或重开页面不会再次自动绑定。原煤煤泥含量及粗精煤泥量的手工点位也可选择。

卡片显示数值、单位、手工补录来源与测量时间；详情显示录入时间、数据库表名及记录 ID。保存成功后重新查询数据库，其他页面/电脑每 5 秒读取一次。KEPServer 断线不影响已存手工补录；补录接口请求失败时仅显示上次查询值并标“待刷新”，无记录显示“—”。手工记录不套用 OPC 的实时过期时间。

右侧“重介精煤”直接汇总左侧“重介精煤灰分”和“重介精煤量”的显示值，不再独立选择点位；旧的右侧点位选择自动清除。两项独立更新，缺失项显示“—”，查询失败时同步标注待刷新，详情分别保留来源和时间。

“浮精”同样汇总左侧“浮精灰分”和“浮精量”，不再独立选择点位，沿用相同的更新、缺失与来源展示规则。浮精压滤机状态、药剂量等因素仍为工况参考，不参与这两个数值的汇总。

此处接入的是决策总览的卡片数据来源，与当前 KEP 卡片相同：不写入 `App.store`，不修改总灰分或建议密度的计算输入，也不改变模型训练与 DS 对拍基线。左侧到重介汇总的连线表示实际汇总关系；左侧选点读数尚未参与建议计算时，汇总到建议密度的连线仍为对照虚线。

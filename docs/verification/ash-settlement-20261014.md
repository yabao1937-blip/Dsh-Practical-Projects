# 小时总灰分延迟结算验证（2026-10-14）

## 口径

- 北京时间自然小时结束两小时后发布并冻结。08:31 最新发布 05:00–06:00；09:00 发布 06:00–07:00。
- 重介化验按采样时间归属 `[开始, 结束)`，仅纳入录入时间不晚于该小时结束后两小时的记录。同小时多条取算术均值，无新增则沿用小时前最近采样；保留采样/录入时间和记录 ID。
- 按每条原决策选择的来源判断：自动/手工来源可采用上述化验，明确选定在线点位不被覆盖。
- 使用原时段粗精预测、浮精灰分和组分煤量重算总灰分，再按原 501+502 实际产量加权。质量不合格、停机、旧批次及断线缺口不由化验补齐；每批最多计 5 秒。
- 独立表 `gpt_ash_settlements` 保存结算结果和分钟分摊贡献。小时列表与分钟区间查询共用结算明细；原小时建议密度、原逐次档案不改写。
- 旧统计缺原始明细时保留参考值，注明未纳入晚补化验，不能虚构分钟明细；完全无有效数据仍为 `—`。
- 后台在独立只读事务中计算，短写事务中去重冻结；每次处理当前到期小时及最多一个历史小时。

- 初轮相关回归：117 项通过，含 DS 原版 `test_training.py` 9 项。
- 投影优化及事务拆分后的受影响回归：65 项通过。

- 迁移测试：6 项通过，覆盖空库和启动已自动建表的已有库。
- `node backend/scripts/verify_recent_ash.js`、`verify_ash_history.js` 通过，覆盖服务器时钟、两小时延迟、跨整点/跨日、缺失值、异步响应隔离及弹窗行为。
- 实际 720 行小时回算从约 2–3 秒降至约 0.8 秒；上线历史处理单小时约 0.01–2.8 秒。HTTP 默认 24 小时统计和分钟接口实测约 0.17 秒。

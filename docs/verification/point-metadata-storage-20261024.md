# 固定点位信息与数据库存储验收

日期：2026-10-24。范围：笔记本测试端；未部署主机、未修改主机配置或数据库，未启动生产采集副本。

## 行为

- KEP 页面显示设备名、通道、测点名称、ITEMID、实时值、状态、采样时间。现有主机的 28 个点位均完整显示。通道由 ItemID 前缀解析，与工艺 A/B 通道不是同一字段。
- 新存储格式把 device、tag_name、item_id、node_id 及关联固定名称放入数据库旁的 `point-metadata/` 不可变文件。含固定信息的 JSON 文档仅保存一个 `$point_meta` 引用；顶层列表按每个记录保存一个引用。
- 文件以完整 SHA-256 命名，先写盘再保存引用。旧点位定义仍能还原，不用当前配置解释历史。缺失或损坏的版本明确报错。
- 普通 JSON、决策压缩归档及永久小时依据均支持新旧格式。SQL 投影必须携带根引用，并在业务消费前还原；投影可忽略未选择的字典子树，不能忽略选中列表的损坏。
- 前端/API 继续获得完整信息。只读测试端从主机授权接口读取点表，不保存本地生产数据库或点表文件。
- 数据库额外保存 `point_metadata_storage` 格式依赖标记，内容仅为格式名。缺少整个点表目录时，备份和离线安装拒绝通过；兼容读取版本回退不会抹除该标记。
- 数据库快照完成后复制并校验点表。离线安装先发布点表再发布数据库，重复安装不覆盖不同内容。冷存储导出是自包含文件，不依赖点表才能恢复。
- 不改写历史记录，不执行数据库压缩；不改变 5 秒采集/显示、60 秒历史入库、液位提前 90 秒对齐及 DS 模型。

## 启用与回退

主应用默认 `DMCS_POINT_METADATA_STORAGE=legacy`：兼容读取两种格式，仍写旧格式。隔离数据库测试已显式启用新格式并核对物理 SQL 内容。

未来部署分两步：先更新兼容读取和备份/安装代码，验证为可回退基线；随后显式配置 `DMCS_POINT_METADATA_STORAGE=compact-v1` 才开启新格式写入。首次部署不能立即写新格式，否则更新失败后旧代码无法读取保留下来的新数据。当前主机未部署、未启用此设置。

## 存储实测的边界

从主机只读取最新记录，在临时目录做无损往返与 canonical UTF-8 大小比较，未写主机：

| 样本 | 原 JSON | 新 JSON | 单条减少 |
| --- | ---: | ---: | ---: |
| 一条决策记录 | 23,436 B | 22,024 B | 1,412 B / 6.0% |
| 一条采集记录 | 472 B | 467 B | 5 B / 1.1% |

对应可复用点表文件为 3,123 B 和 136 B，首次写入另占文件空间。以上不是全天统计，不含索引、页分配、WAL 和备份，不能直接外推每天节省量。历史记录不重写，因此现有数据库不会立即变小。

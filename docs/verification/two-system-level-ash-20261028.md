# 按系统开启数自动选择粗精煤泥灰分预测方案 · 2026-10-28

## 需求与口径（用户两次澄清后确定）

- 现行粗精煤泥灰分预测链（expert 模型 + 全部因子；粗精煤泥量 = 入洗 ÷ 24）**适合系统开启
  数 ≥3 的状态**，完全保留。
- 系统开启数**恰好 = 2** 时，粗精煤泥灰分预测改为**纯液位查表**：精磁尾液位 ≥30 → 默认
  **14%**，<30 → 默认 **15%**；其余模型因子（原煤灰分、带煤量、系统、脱粉等）**暂时不参
  与**该逻辑。液位采不到（缺失/过期/单位不符）→ 灰分按缺失处理，不造数。
- 四路系统状态（401/402/A/B）任一路未知时**不能证明两系统**，维持现行模型链（模型链自身
  会因该因子缺失而暂缓）。开启数 <2 未特别规定，同样走现行链（停机由既有 is_stoppage 闸门
  处理）。
- 附带（任务 2）：浮精量「默认 40」改 15——经查 40 为主机 `auto_state` 的
  `amountInputs.floatAmount.manual`（2026-09-21 录入的存储值，代码与种子库均无硬编码），
  需在主机决策总览浮精量卡片改录入为 15（压滤机板数折算与表2记录优先级不变）。

## 实现

- `backend/app/services/decision_live.py`：
  - 新增 `running_systems(cells)`（四路状态全已知才返回计数）与
    `TWO_SYSTEM_ASH`（two-system-level-ash-v1：running=2, threshold=30, 14/15）。
  - `calculate()` 在模型链之前判定：恰好两系统 → 粗精煤泥灰分 = 液位查表（液位沿用/
    停机时标 held 仅供观察），`input_derivations.coarse_ash` 记录方案与观测液位（方案切换
    会形成新的小时上下文指纹）；三组分总灰分与调密建议继续用该灰分按既有流程计算。
- 粗精煤泥量（÷24）、浮精/重介链路、DS 对拍基线均未改动（amount.py 保持原样）。

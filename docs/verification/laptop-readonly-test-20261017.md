# 笔记本只读测试服

用户确认的范围：笔记本运行自己的前端和后端代码，默认只读生产主机数据；生产主机独占采集、补录、配置保存和小时后台结算。

## 接入方式

- 生产主机：`10.255.2.7:8000`。原 SQLite 继续本地运行，不共享数据库文件、不下载副本。
- 笔记本：`127.0.0.1:8000`，只绑定回环；当前生产网地址 `10.255.2.6`。
- 主机新增可选的 `/api/v1/readonly-db` 查询接口，以专用随机凭据和精确客户端 IP 授权，默认未配置时关闭。
- 查询连接使用 SQLite `mode=ro`、`query_only` 和 authorizer；拒绝写入、DDL、ATTACH、可变 PRAGMA 和扩展加载。
- 主机最多四个读取事务，笔记本连接池最多三个。连接归还即结束读取快照，遗留快照超时回收。
- 笔记本跳过建表、迁移、视图创建、后台结算、采集和写 token 创建。写 API 即使从 localhost 调用也拒绝，纯计算 `POST /decision/snapshots` 保留。
- 网页不加载笔记本旧业务库或演示种子，不发送整库镜像和旧补录重试。主机读取失败时隐藏业务正文并显示错误，不回落本地 SQLite。

## 配置和启动

主机专用配置是 `backend/config/readonly-access.local.json`，笔记本专用配置是 `backend/data/remote-readonly.json`。两者均已忽略，凭据不可提交。测试时 `backend/conftest.py` 显式设置临时数据库隔离标志；普通 `DMCS_DATABASE_URL` 不得静默绕过只读配置。

主机第一次接入需要下载 `ReadOnlyBridge.zip`、全部解压后运行 `EnableReadOnlyTest.cmd`。安装只验证并备份八个指定源文件，创建这一份专用访问配置，短暂重启属于本安装目录的 Web 服务；不打开、备份、迁移或恢复数据库，不重启采集器。源文件或配置冲突直接拒绝，失败恢复原代码及新增配置。

笔记本继续使用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File backend/scripts/start_server.ps1
```

`/api/v1/runtime-mode` 应返回 `readonly-test`；`/api/v1/health/live` 表示本地代码运行，`/api/v1/health/ready` 验证主机数据接入。

# 整点决策闪值与液位越界建议修复（2026-10-14）

## 已确认原因

- 10:00:17 服务日志出现 SQLite `database is locked`；即时请求耗时 9.5 秒，小时请求最高 26.6 秒，超过前端 8 秒超时。旧 `tick` 在写锁内完成小时还原、聚合和旧证据压缩，采集进程同一时段记录 OperationalError 并重新连接。
- 逐次档案显示 10:00:50 液位 75.12 时暂停、10:00:55 液位 74.57 时恢复、10:01:00 液位 75.72 时暂停、10:01:10 液位 74.33 时恢复。采用的是提前 90 秒液位。小时建议受当前即时保护约束，因而两张卡片同步变化。

## 新行为

用户确认液位超出专家基准不再影响密度建议。GPT 仍采用原模型的 25–75 边界估算，仅取消该条件对建议的拦截；不外推、不重训，不变更模型系数、DS 或历史档案。保留 0–100 合法范围、缺失/过期、停机、调密保护及小时有效建议覆盖率规则。旧模型产物中的 `level_policy` 属于训练时元信息；实际决策行为以本次运行时规则为准，页面说明同步更新。

每 5 秒观察记录提交后，才通知独立维护任务。小时汇总和归档的读取、还原、压缩在一致性只读事务中完成，提交阶段短暂持有写锁并复核；归档写入和删除对应热记录保持原子性，原始采集引用保护不变。维护失败独立重试，关闭时等待在途任务完成。

小时统计尚未生成时，HTTP 返回明确的 `pending`，页面按原轮询周期等待后台结果，避免多页面各自启动重复的整小时计算。卡片悬停提示等待或暂停原因，正文和布局保持原样。前端 8 秒超时未放宽。

# 第三批续：只读测试服十小时定向回算

## 范围

继续四批计划的第三批，解决主机后台每次只处理两个小时导致测试服等待的问题。只部署笔记本测试服，不更改主机 worker、生产数据库、采集或配置，不建立本地数据库副本。DS、训练模型、共享证据求解器、原有布局不变。

## 行为

1. 小时表先批量读取主机已保存的结果。最近十小时有过期/未结算项时，关闭展示事务并释放 display 通道，再在 calculation 通道开启新主机读快照，按最新有效化验本地回算。
2. 内存缓存最多十小时、32 MiB 的估算 JSON 数据；按原始来源修订复用不可变组分证据，按化验 revision 更新结果。缓存不持有会话或连接，不写主机、笔记本旧库或浏览器存储。
3. 新回算仍调用原 `build_settlement`、`weights`、`replaced_total` 和 `contribution_item`。实际生产时间/旧偏移兼容、同小时最新采样、向前沿用且不越过下一真实采样、未来过滤、显式在线来源、无效组分排除、质量加权和停机覆盖口径均保持。
4. 小时建议通过可选 `settlement_reader` 使用同一只读提供器；既有固定 MD_SET 基准、严格超过 80% 灰分覆盖和真实配置变化保护不变。生产调用不注入，行为保持原路径。
5. 主机尚未冻结覆盖率时，每次回算重新检查停产证据；识别主机后来冻结的覆盖率，避免点位停用/定义变化后把未封存的旧停产区间错误地冻结在内存中。
6. 本地派生结果带 `calculation_origin=readonly-local-replay`；小时表及小时建议悬停说明明确“测试服只读回算，未写入主机”。主机已保存的有效结果优先使用，不添加该标记。
7. 小时表响应缓存从五秒减为一秒，测试服前端每 5 秒检查（叠加原五秒页面节拍，通常约 5–10 秒）。生产页面原节奏不变。计算和展示预算仍各一个生产者，不增加连接池、重试或并行采集。

## 证据读取优化

旧结算 contributions 只有总产量、灰质量和是否替换化验，缺少逐次重介组分煤量，不能精确反推修正系数。因此先保留一个无损 SQL 投影加载器作对拍，再实现独立的 `settlement_kernel.py`：只读取原公式实际使用的字段与全部 resolved_choices，只展开必要采集/人工引用。

引用在 SQL 传输前裁剪 fields/overlay，原始采集 sample 也只读取所需属性；原共享 resolver 和完整归档读回不改。归档先校验完整解压内容的 SHA256；不支持的证据结构交回无损加载器，不猜测或补零。

## 十小时真实证据只读实验

脚本：`backend/scripts/profile_readonly_replay.py`。在同一主机只读事务、固定主机时刻，读取最近十个真实生产小时。第二轮输入虚拟化验变化，只测试本地计算；**未插入化验、未写数据库、未向运行中的页面发布虚拟结果**。

## 隔离验证

- 三个读者通过真实认证只读 SQLite 桥接并发读取十小时晚补结果。主机不运行结算 worker，十小时均由本地回算更新，旧结算快照逐值不变，事务和池连接全部释放。测试模拟十秒页面检查并验证总时延小于三十秒；该隔离协调测试每小时一个样本，计算规模另由上方真实十小时实验覆盖。
- 小时建议注入测试验证：旧结果建议 1.460，新回算灰分对应 1.480；固定 MD_SET 基准和原数据库 dump 不变。未注入的默认调用仍给原结果。
- 无损投影 29 项、精简内核 19 项、内存缓存 22 项独立测试通过，包括 JSON 精度、引用、冷热一致、异常拒绝、来源变化、时钟回退、未冻结覆盖率变化、后续冻结、大小限制及并发复用。
- 322 项完整后端组合回归通过，278.60 秒；包含 DS 原版 9 项、归档/备份、结算/覆盖率/固定基准、只读启动与真实池并发等既有链路。唯一 warning 是既有 Starlette/httpx 弃用提示，JUnit 记录为 `output/pytest-local-replay-20261017.xml`。
- 11 组前端 VM 回归通过；最后缩短轮询后再次全部通过。小时表和小时建议的只读回算悬停来源均有断言，默认生产和 DS 分支保持。
- 真实 Chrome 三页面在初始化完成后同时进入总览，均为 18 节点、10 行小时灰分、相同生成时间，小时建议 1.500，采集/手工读取正常，观测无 HTTP 错误或失败请求。截图 `output/playwright/readonly-local-replay-20261017.png` 已目视核对；QA 浏览器关闭。
- 最后缩短到五秒检查后，再用新的三页面验证：每页观测三次小时表请求，间隔 4.87–9.99 秒，18 节点/10 行及采集正常、HTTP 错误 0；未把 VM 测试替代真实新增轮询检查。

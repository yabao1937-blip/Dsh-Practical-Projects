# 主机冷缓存重算与连接池耗尽修复

2026-10-16 主机 10.255.2.7 的诊断日志确认 SQLAlchemy `QueuePool size 5 overflow 10` 被占满，新请求等待 30 秒超时；后台采集同时反复报告 `OperationalError`。早期健康检查可短时在 0.5 秒内返回，随后页面及健康检查超时，不能将页面的“后端离线”等同于进程从未启动。诊断未发现磁盘空间不足（剩余约 65 GB）。

## 修复

- 小时灰分表、小时建议 GET 只读取当前口径的有效缓存；缺失或修订后过期返回明确 pending，由已有最后有效建议显示逻辑保留参考值。GET 不执行同步历史重放，不把旧 v3 缓存作为 v4 有效值。
- 后台单一维护队列优先最新发布的十小时，每次最多准备两小时；晚补化验本小时及后续沿用时段仍会更新。
- 小时表使用纯范围校验，避免先读取旧小时快照后又重放结算。
- `/health/live` 为不占同步工作线程的异步轻量检查。数据库健康检查超时后检查存活状态，进程可达显示“后端繁忙”；真实数据库 503 保留“数据库未就绪”，采集状态独立展示。
- 查询补丁安装配置严格限定六个查询/前端文件，备份原源码、保留现有已校验全量数据库备份，不进行数据库迁移或复制。升级失败回滚源码，继续保留生产数据库。停止程序识别本安装的 serve.py，涵盖尚存活但没有监听的卡死进程，保留采集及其他安装。

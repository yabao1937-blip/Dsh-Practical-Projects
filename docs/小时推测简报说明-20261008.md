# 小时推测简报

新页面替换原“三表 1h 对齐”页面。旧离线计算器保留用于兼容和原版对拍，页面与导入入口均不再调用它。

## 生成与保存

- 后端服务启动时启用任务，从下一北京时间整点开始，每小时一行。首次启用前的小时不补生成。
- 关闭浏览器不影响任务；需要后端服务持续运行。每个整点是唯一主键，多进程或重复执行不产生重复行。
- 每行冻结输入、来源、采样/接收时间、默认及沿用标记、模型参数、计算结果和建议理由。后续补录和模型切换不改写已保存行。
- 服务中断错过的整点保留缺失行，注明未完成快照，不用当前配置回算过去。允许任务在整点后 90 秒内完成，以整点为取数截止时间。
- 新表 hourly_brief_schedule、hourly_brief_rows 不属于旧 /state 整库镜像。
- 新迁移 0006 接续工作区现有业务补录迁移 0005。当前现场库原来使用启动自动建表且未登记 Alembic 版本；此次也通过既有启动机制建立新表，未盲目 stamp 旧库。直接在此类旧库执行全量 alembic upgrade head 会因旧表已存在失败，应先独立核对旧库基线。

## 取数口径

KEP 记录必须在整点前已接收、质量有效、配置定义一致且未超时。手工补录同时要求采样时间及录入时间不晚于整点，按采样时间取最近记录；不把后录入的历史化验当成当时已知。

| 原煤灰分 | 202/ASH_R_INS；实际读到 0 沿用整点前最后非零值，注明设备停机 |
| 入洗原煤量 | 301/COAL_CAP；用户已确认 t/h；实际读到 0 同样沿用并标停机 |

| 粗精煤泥量 | 业务补录 coarse_slime_amount、旧手工量；再按已有筛上量减筛下水量计算；无固定量兜底 |

| 总灰分 | 三组分灰分按对应煤量加权 |
| 建议密度 | 使用该小时输入调用原密度建议纯函数，保留容差、单步上限及动作保护 |

默认值和沿用值均明确标注。模型十因素缺任一项时不以均值补全；未配置的展示项（例如药剂量）不会额外阻断其他计算。停机因子沿用既有口径：有效原始入洗量 ≤10 t/h 为 1，否则为 0。

总灰分要求三组分灰分、煤量完整有效且总量大于零。当前密度超出原建议算法范围 1.350–1.600 时保留实测显示，但建议列为空并注明原因，避免边界钳制产生超过单步限制的跳变。停机沿用值参与快照推测时保留标记，不能据此将停机期间累计为实际产量。

为保证真正取到整点前最近一次 5 秒读数，采集跨整点覆盖 latest 前会额外留存前一条原始快照；普通分钟历史和原值保持原口径。

## 页面与导出

- 18 列：整点时间 + 用户指定的 17 个指标；最新在前，日期筛选，固定时间列、横向滚动。
- 刷新仅读取已保存行，不提前生成。点击整点时间查看来源、原采样时间及完整缺失/建议理由。
- Excel 导出使用项目已有 openpyxl 依赖，由 backend/scripts/generate_hourly_brief_xlsx.py 生成真正的 XLSX，包含小时明细、数据来源与说明两张表。导出绑定当前页的整点主键，与页面快照一致。
- 只读 API：GET /api/v1/hourly-brief，GET /api/v1/hourly-brief/export。

## 同步与升级

`GET /api/v1/state` 新增 `_revision` 和 `heavySamples`。普通 `PUT /state` 必须携带读取时的 `_revision`；成功返回 `revision`，冲突返回 HTTP 409。版本比较和覆盖写入位于同一 SQLite 写事务。记录数守卫继续防止误删；明确的本机备份恢复仍使用 `force=true`。

第一次打开升级后的页面，若发现旧本地数据没有版本号，页面会保留本地数据并提示核对。先导出备份，再使用“从服务器恢复数据”建立新的同步基线。旧版本客户端不会被允许覆盖新服务端数据。

`POST /api/v1/samples/heavy-ash` 接受 `client_id`。同标识、同内容重试返回已有记录；同标识、不同内容返回 409。采样时间需为有效的 `YYYY-MM-DD HH:MM:SS`，密度范围 1.300～1.650，灰分范围 0～100%。新增 `GET /samples/heavy-ash`。

新服务启动时会执行 SQLite 结构升级：保留历史行，将煤样唯一键加入皮带，并为采样增加客户端标识。已在临时旧结构数据库验证重复升级和数据保留；本轮没有启动新代码连接现场数据库，尚未执行现场升级。

## 数值影响与验证

简报合成夹具共 24 行，其中 23 行数值变化。首小时原先误用后来的重介灰分 8.40%，现使用当时的 8.50%；该行核算总灰分由 8.79% 变为 8.88%，建议密度由 1.431 变为 1.425。此结果说明历史时间对齐的影响，不代表现场产线改善。

同一训练夹具上，MLR 留一 Q² 从 0.421497 变为 0.420602，PLS 留一 Q² 从 0.433741 变为 0.419612；PLS 时间验证 Q² 从 0.1399 变为 0.1718。最终仍选 PLS，分量数为 2。存量现场模型没有自动重训；这些分数不能替代后续独立实测验证。

验证包括：151 项 pytest、前后端金标准对拍、独立单特征逐折验证、7 项 Edge 浏览器回归，以及数值补录、采样重试、双皮带导入和版本冲突的 Node 回归。测试数据库均为临时 SQLite。远端 CI 配置已更新，尚未提交或推送，因而未触发远端运行。
